## 退出时弹「是否保存」卡死 —— 根因与修法（2026-11-05 追加）

用户反馈：程序退出时 AutoCAD 弹「是否保存 Drawing1」，没人点就卡住，每次都得手动点「不保存」。

- **AutoCAD 根因**：清理时用 `Documents.Item(n).Close(false)` 关图纸，AutoCAD 2020 实测直接
  **E_FAIL 0x80004005**，图纸关不掉；异常又被 `with _ -> ()` 吞了，于是 `Quit()` 时图纸还带着改动 →
  弹模态框 → 客户端卡死。**必须用 `Application.ActiveDocument.Close(box false, Type.Missing)`**
  （Item 取出来的对象 Close 会失败，ActiveDocument 取出来的同一张图却能关）。
- **Excel 同样有**：`Quit()` 前只要还有改过没存的工作簿就弹保存框，而且 `DisplayAlerts=false`
  压不住；`Quit()` 2ms 就返回了，进程 30s 都不退（隐藏进程 + 隐藏对话框）。必须先
  `Workbook.Close(SaveChanges=false)` 再 Quit。
- Excel 另一个已知毛病：**客户端还活着时，Quit 后 EXCEL.EXE 进程不肯退**（实测 release RCW / GC /
  FinalReleaseComObject 都没用；只有在不会话结束/进程退出时才没了）。所以测试里给 Excel 8s 宽限后结束进程，
  不判失败；Word/AutoCAD 必须自己退（有断言）。
- **产物**：`AutoCADHost.Host` 新增 `CloseActiveDocumentWithoutSaving` / `CloseAllDocumentsWithoutSaving` /
  `QuitWithoutSaving`；`ExcelHost.Host` 新增 `CloseAllWorkbooksWithoutSaving` / `QuitWithoutSaving`。
  都是"先丢改动再退"，只对**自己起的实例**用（用户手上开着的实例别碰）。
- 测试 `shutdown` 改成带 graceMs 参数；收尾断言 AutoCAD/Word 不能被强杀。整轮从 ~50s 降到 ~32s，连跑 3 次全绿、无残留。
- 注意：AutoCAD 用 COM 启动时**总会**带一张临时 Drawing1（跟 STARTUP 设置无关），自动化躲不掉；
  现在这张图只做临时用，退出时丢弃、不落盘、不弹框。

## 两种执行方式（追加）

方式一「一条命令」：各 host 库加 `exec` / `execQuery`（语义照参考项目 WordHost.Host.exec）——
起实例 → 跑一段活 → 关掉，host 不留。与参考项目的差别：碰到「已有实例在跑」不弹框求人退出，
直接返回 `Error`（库不该弹框，也不该把用户的实例关掉）。收尾固定 `quieten`（Visible=false、
DisplayAlerts 关）→ `QuitWithoutSaving` → `release`（FinalReleaseComObject + GC，Excel 不退就是这原因）
→ 等进程 → 超时结束。

方式二「合作完成」：新项目 `HostSession`（netstandard2.0，引用三个 host）。
- `Host.openSession kind` → `Session { Id; Kind; App(App DU); Owned; Pids }`；`Id` 即「地址」（`word:15324`，复用用户实例时是 `excel:existing`）。
- `Host.execByAddress id action`（或 `exec`/`execWord`…）→ 执行一步，**不关 host**，结果 `Result<'T,string>`。
- `Host.close session` → 按「第一步之前的状态」收尾：`Owned=true` 才关（丢改动 + Quit + 清残进程），否则一个字不动；同时把地址从地址簿移除。
- 所有 COM 调用排在**同一个 STA 线程**（BlockingCollection 队列）：会话是长活的，RCW 跨公寓会被封送、要求创建线程泵消息，所以固定一个线程。
- 地址簿只在进程内有效；跨进程要另加一层（把 Id 里的 pid 映射回 ROT 实例）。

测试：`xUnitHost/CollaborationTest.fs` 两个 Fact（方式一/方式二），断言 host 中途不关（pid 还在、内容累积）、收尾后 pid 消失、无残进程。
坑：xunit v3 的 `[<assembly: CollectionBehavior(DisableTestParallelization=true)>]` 没生效，得加 `xUnitHost/xunit.runner.json`（`parallelizeTestCollections: false` + `CopyToOutputDirectory`），否则两个 COM 测试并行抢实例。
验证：5 个测试全通过，整轮约 47 秒，连跑 3 次无残进程。

## 跨进程「凭地址回来」（2026-11-05 追加）

目标：`word:15324` 这种地址不只在本进程好使 —— 换一个进程也能接回同一只 host。

先照官方文档核过，两条结论（省了很多瞎试）：
- **ROT 的 `IRunningObjectTable::Register` 是给服务端登记的**（文档写明 server 在 `IOleObject::DoVerb` 时登记自己）。
  我们作为客户端拿着别人的代理去登记，实测 flags=0/1/2/3 全都返回 `E_INVALIDARG`。别在这条路上耗。
  Office 进程自己已经把 Application 登进 ROT 了，所以「拿运行中实例」的正路是 `GetActiveObject`。
- **`AccessibleObjectFromWindow` + `OBJID_NATIVEOM` 要求 hwnd 是「最内层文档窗口」**：
  Word 是 `_WwG`、Excel 是 `EXCEL7`（XLDESK 的子窗口），不是顶层 `OpusApp`/`XLMAIN`。
  敲在顶层窗口上一律 `E_FAIL`（我用 Progman 验证过 P/Invoke 声明本身没问题）。
  这条路能给到「按 pid 精确挑多实例」，但还要 EnumChildWindows + 每类窗口名，暂未实现。

落地方案（`HostSession/Host.fs`）：
- `resolve address : Result<Session,string>`：同进程先查地址簿；跨进程则
  ① 解析出 `(kind, pid)`；② 确认该 pid 还在（`Process.GetProcessesByName`）；
  ③ `GetOrCreateApplication()`（ROT/GetActiveObject）；④ **核对应用主窗口归属的 pid**：
  Word 用 `ActiveWindow.Hwnd` + `GetAncestor(GA_ROOT)`（Application 本身没有 Hwnd），
  Excel 用 `Application.Hwnd`，AutoCAD 用 `HWND`；对不上就 `FinalReleaseComObject` 放掉并报错
  （机器上多实例时 ROT 只暴露一只，这种情况不许乱动）。
- 地址自带归属：带 pid = 当初自己起的（`Owned=true`，收尾要关）；`existing` = 用户手上那只（不许动）。
  解析出来的 Session 同样带 `Pids`，`close` 逻辑不用改。
- 新增 `Host.closeByAddress`；`execByAddress` 改走 `resolve`。

验证：新项目 `CrossProcessWorker`（net10.0 控制台，只依赖 HostSession）当「第二个进程」，
测试 `方式二 跨进程：另一个进程只拿地址回来，说的还是同一份文档`：
父进程 pid 7572 开 Word 写下第一句 → 地址 `word:7572` → 子进程 pid 3592 仅凭地址接上、
追加第二句并打印 → 父进程读到同一份文档。6 个测试全绿（55s/轮），连跑 2 次无残进程。
子进程 stdout 用 UTF-8（worker 里显式设 `Console.OutputEncoding`），否则中文在重定向时变 GBK 乱码。

## 地址升级：带上「最后一次实质性保存的时间」（2026-11-05 追加）

只有 pid 不保险：进程会退、pid 会被系统复用、文档会被换掉或被人另存一次。
地址改成**一整套指纹**，回来逐项核对：

    word:7572:1793863068197:1793863070426:790cb57f:w
         pid  进程启动毫秒   最后保存毫秒    路径指纹 归属(w/u)

- **最后保存时间的来源**：锚定文档在磁盘上的 `FileInfo.LastWriteTimeUtc`（Unix 毫秒），
  **不用** `Document.Saved`——那个只说「有没有未保存改动」，说不出上次保存是什么时候。
  新文档还没存过盘 → `0` + 路径指纹 `-`。
- **路径指纹**：绝对路径小写后 SHA256 前 4 字节（8 位 hex）。地址里放不下整条路径，
  但「换没换文档」必须能看出来，所以放哈希。
- **进程启动时间**：防 pid 复用。`Process.StartTime` 转 Unix 毫秒，跨进程一致。
- **归属** `w`/`u`：w = 本次起的（收尾可关），u = 你原来就开着的（一个字不动）。
  老地址 `word:7572`（无指纹）、`excel:existing` 仍能解析，但 `Session.Drift` 里会注明「没核过」。

API 变化（HostSession）：
- `Session.Id` → `Session.Address`，新增 `Stamp`（现场快照）、`Drift: string list`（漂移说明）。
- **`exec` / `execWord` / `execByAddress` 返回 `Result<'T * Session, string>`**：
  执行完重新拍快照，文档被保存/换掉地址就变；老地址会被地址簿移除，再拿它回来会被核对挡下。
- `resolve`（严格）/ `resolveWith Drift.Lenient`（只认 pid+启动时间，漂移记在 `Drift` 里放行）；
  `closeByAddress` 严格失败后自动退到宽松——收尾只关心「是不是同一只进程」。

坑（都踩过）：
- **Word 冷启动是 0 份文档**，`ActiveWindow` 直接抛 → `appPid` 拿不到 pid → 地址成了 `word:0:0:0:-:w`。
  改成三级回退：主窗口反查 → 调用方已知 pid（自己起的进程 / 上次快照）→ 机器上这种进程只有一个就是它；
  都不成立记 0，核对时跳过 pid 项。
- **RCW 按 IUnknown 身份缓存**：`resolve` 失败时对 `GetActiveObject` 新拿到的 app 调
  `FinalReleaseComObject`，会把**会话里那只**一起拆掉（再摸就 `InvalidComObjectException`）。
  改成 `Registry.tracked app` 判断「这只我们手上已经有」，只放真正没见过的。
- `Assert.NotEqual(a, b)` 在 F# 里对 string 有二义性（`'T` vs `'T seq`），用 `Assert.True(a <> b)`。

验证：`指纹：地址带着最后一次实质性保存的时间，保存过之后老地址就作废`
（新文档 saved=0 → SaveAs 后 saved>0 且地址变 → 老地址被拒并报出新地址 →
外部改文件时间后严格拒、宽松接回带 1 条漂移）。7 个测试全绿，55–58s/轮，连跑 2 轮无残进程。

## 进 host 的两条路要分开（2026-11-05 追加，用户指出）

首次进入 ≠ 按地址回来：
- **首次进入 `openSession`**：对外签约。可以从无到有起一个进程、记「谁起的」（收尾按原状态关）、
  AutoCAD 还要等冷启动就绪 → 用 `GetOrCreateApplication()`。
- **按地址回来 `resolve`**：harness 内部交接，同事之间打个招呼。只接 ROT 里现成的那只 →
  用 `TryGetRunningApplication()`（三个 host 库新增，`tryGetRunning` 的公开版，**绝不新建**）。

改前 `resolve` 复用了 `GetOrCreateApplication`，语义上埋了个雷：地址说的人不在，它会顺手起一个新的，
调用方还以为接回了原来那只（Excel 还会顺手补一本空白工作簿）。改后没有实例就报错：
「接不上 xxx：现在没有可接的 xxx 实例。按地址回来只认现成的那只，绝不新建」。

顺带收紧归属：`Owned = spec.Owned && spec.Pid > 0` —— 地址里没有 pid 就证明不了是自己起的，
一律按「你手上的」处理，收尾一个字不动。

测试：新增 `按地址回来只打招呼：没有实例就报错，绝不新建一个`（`excel:0:0:0:-:w` → 报错 + 断言没冒出 EXCEL 进程）。
8 个测试全绿，56.6s。

坑（都已修，记进 gotchas.md）：
- **Excel 互操作参数按值传 `object`**（`Open(path, box 0, box ro)`），Word 才是 `obj&`；混用报 FS0421/FS0412。

- 只读属性会挡住 `File.Delete`（`Access denied`）→ 删前 `FileInfo.IsReadOnly <- false`。
- F# 不允许 `try/with/finally` 连写，得「先算结果、再单独收尾」。
- 清单文件别写 BOM，否则按 `"OK\t"` 匹配会漏第一条。

## 带宏 xls 转 xlsm + 别顺手拉起 AutoCAD（2026-11-05 追加）

用户三条要求：① 那两份带宏的 `Pumps*.xls` 转成 xlsm 再删老文件；② 以后默认自动转，没宏转 x、有宏转 m；
③ 报了个问题——操作 Excel/Word 时连带把 AutoCAD 启动起来了。

### 1. DocConvert 支持 .xlsm
`convertBook` 改成：先打开书判 `HasVBProject`，**有宏就存 `.xlsm`（FileFormat 52）**，没宏才存 `.xlsx`（51）。
存完读回来两件事都要过：格子值指纹一致、**宏还在**（`hasVba back` 为真），否则判失败、原件保留。
`Paths` 加 `existingTargetOf`（删原件时先看 .xlsm 在不在，再退 .xlsx），`delete` 用它。
顺手把 `bookPrint` 里那个真·控制字符 `'\x1f'` 改成转义写法 `'\u001f'`，源码里不再有不可见字符。

实跑：Pumps.xls(11.4MB) → Pumps.xlsm(603KB)、Pumps-pc.xls(13.5MB) → Pumps-pc.xlsm(711KB)，
逐格比对 15064 / 18009 个值全一致；两个 xlsm 里都有 `xl/vbaProject.bin`（9216 字节）。原件已删。
备份目录 `C:\崔胜利\_doc转换备份_20261105` 用户确认后整个删掉（删前逐份核对 28 个新文件都在）。

### 2. AutoCAD 是被谁拉起来的
查过：DocConvert 只引用 WordHost/ExcelHost，代码里没有一个 acad 字样；也扫了转换出来的 23 个含
OLE 嵌入/外部链接的文件，`acad|autocad|.dwg` 命中 0 —— 不是文档里的嵌入对象触发的。
**真凶是全量测试里的「三个主机互相打招呼」**：`GetOrCreateApplication()` 语义就是「没有就新建」，
acad 没开着时它当场起一个（AutoCAD 没有隐藏启动，窗口真弹到用户脸上），用完再关。

修法：`Greeting.mayLaunchAcad()` —— 只有 `XUNITHOST_LAUNCH_ACAD=1` 才允许从零起 acad。
没开就跳过这一段，报告里明说「本机没在跑，这一段跳过」，结论也改成「两条通道通了；AutoCAD 没测」，
不再谎报「三条都通了」。`run-facts.sh -a` 跑前也打印提示。
另外顺手修了个更隐蔽的坑：`acadSay` 原来在用户已开图纸时直接往 `ActiveDocument` 写 TEXT（污染用户的图），
改成一律 `Documents.Add()` 开临时图，`finally` 里 `Close(box false, Type.Missing)` 关掉。

全量回归：9 个用例全通过，77.8 秒，acad 全程没被起，跑完无残留进程。

## 测试拆段 + 动笔前先认人（2026-11-05 追加，用户指出）

用户两条：①「不是应该分开开吗？咋三个帮一起了」②「你写东西前应该核对文件名和最后实质保存时间」。

### 1. 一段通道一个 Fact
原来一个 Fact 把 Word/Excel/AutoCAD 全开一遍，等于跑一次把三个程序都拉起来。拆成：

## 项目拆分重排：OS 单独立一层，公用往测试项目前部收（2026-11-05 追加，用户看的方案）

用户两条：①「没必要建这么多的小项目，各专门的放各自的 host，公用的放测试项目的前部」
②「操作系统线程、进程操作之类的可以单独建设一个项目」。

改完的项目（7 个，四层）：

```
OsHost            操作系统层：STA 线程、进程账本、窗口→pid、时间/文件时间、COM 底层、异常归因
WordHost          各管各的：取实例 / 认自己是谁 / 收尾 / 一次性 exec
ExcelHost
AutoCADHost
xUnitHost         前部 Common.fs（报告、认人、忙重试）+ Session.fs（会话层，原 HostSession）；后面各 Fact
DocConvert        批量转换工具
CrossProcessWorker 第二进程，链接 xUnitHost/Session.fs
```

### 为什么这么分
- `procIds` / `waitGone` / `killPids` / `runInSta` / `explainException` / COM P/Invoke 原来
  **在三个 host 里各抄一遍**，HostSession 里还有第四份。全部收进 `OsHost`，现在只有一份。
- 「我是谁」是各家自己的事：`WordHost.Host.identity` / `ExcelHost` / `AutoCADHost` 各自拍
  `OsHost.Identity`（pid、启动毫秒、锚定文档、最后保存、有无改动）。会话层的 `snapshot`
  只剩「pid 判不出来时的三级回退」。Word 的 pid 要从 `ActiveWindow.Hwnd` 往上找 OpusApp，
  Excel/CAD 有 `Hwnd`/`HWND` —— 这知识本来就该在各自的库里。
- `HostSession` 这个 849 行的单文件项目整个散了：OS 部分进 `OsHost`（约 500 行），
  剩下的会话编排进 `xUnitHost/Session.fs`（约 460 行），命名空间 `HostSession` → `XUnitHost`。
- `CrossProcessWorker` 不能引测试项目，就把 `Session.fs` **链接**过去
  （`<Compile Include="..\xUnitHost\Session.fs" Link="Session.fs" />`），规则只一份源文件，
  不再为它单开库项目。这是「少开项目」和「不抄第二份」之间的取舍。
- 报告助手原来在 `CollaborationTest.fs`（`Report`）和 `HostGreetingTest.fs`（`Greeting`）
  各写一套 `title/line/conclusion/displayWidth/pad` —— 合并进 `Common.fs` 的 `Report`。

### 顺带修的一个副作用
`Word 和 Excel 打招呼` 原来不 `requireClean`，跑一次就在用户开着的 Word 里留一份「文档1」
（正文「Hello Excel. -- Word」）。改成 `Say.word` / `Say.excel` 把新建的那份**交回来**，
收尾 `Close(box false)` 关掉。以后碰到用户开着的实例也不留垃圾。

### 验收
- `dotnet build xUnitHost.slnx -v q`：0 警告 0 错误。
- 全量：11 个用例 **10 通过 / 1 跳过（acad 没开）/ 0 失败**，77.7s，跑完 WINWORD/EXCEL/acad 全 0。
- 会话层单独验过一遍（fsi，Excel 一条线）：开 → `excel:12836:...:0:-:w`（Owned=true）→
  写 A1 → 地址不变 → `resolve` 成功 → `close` 后 EXCEL 进程归零。
- Word 的 `identity` 用只读方式验过：pid 8564、启动 18:23、锚定临时 docx、最后保存对得上。
- 收拾掉一只 **上一轮测试留下的 Word**（pid 8564，里面只有「Hello Excel. -- Word」和一个
  中断的指纹测试留下的临时 docx）—— 那 6 条要干净起点的 Fact 就是被它挡住的。

### 坑
- `Error.explain` 会跟 `Result` 的 `Error` 情形打架 → 模块改名 `Errors`。
- F# 模块顺序：`Proc.startedMs` 用 `Clock.unixMs`，`Clock` 必须写在 `Proc` 前面。
- 闭包里 `&clsid` 拿到的是 `inref`（参数不可变）→ 先 `let mutable id = clsid` 再 `&id`。
- `app.Documents.Item(box i)` 也过不去（签名是 `obj&`）→ 用 `Seq.cast<Document> app.Documents` 枚举。
