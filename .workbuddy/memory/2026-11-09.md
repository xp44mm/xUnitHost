## 新增 AutoCADHost.Application：按 PID 挂回 COM 根对象（11:4x）
- 用户要「给一个活着的 acad PID，取它的 Application 和其他根对象（如 HostApplicationServices）」。权衡后定边界：**COM 跨进程只能拿 AcadApplication + 它直属的 Documents / ActiveDocument / Preferences / MenuGroups / AcadState**；`HostApplicationServices.Current` / `Core.Application` / `DocumentManager` 是 AutoCAD 进程内 .NET 静态单例，COM 代理看不见，读它们走 `AcadMgdHost` 的 `XH_DB`（已在读 `HostApplicationServices.WorkingDatabase`）。模块里用 `Application.boundary` 三行写明，不假造。

- `OsHost/OsHost.fs` 的 `Com` 新增 `CreateBindCtx` / `bindContext` / **`runningEntries : unit -> (string * obj) list`**（枚举 ROT、逐条取显示名与对象，单条失败跳过，上限 512，绝不新建）。黑板模式仍走 `runningAt` 不枚举。

## Application 模块加异步入口 GetApplicationAsync（13:4x）
- 用户点名 `Application.fs#178-184`（`byPid`）要异步版，名字按 .NET 约定定为 `GetApplicationAsync`。
- `OsHost.Sta.runAsync : (unit -> 'T) -> Task<'T>`（新）：仍是同一个 BlockingCollection 固定 STA 队列，泛型 `TaskCompletionSource<'T>` + `RunContinuationsAsynchronously`；不阻塞调用方、不占线程池线程干等，**续体不许同步跑在那条 STA 线程上**（否则续体里再调 run/runAsync 会自己等自己）。原 `run` 一行没改。

## 异步返回值改为 Task<T>，不再包 Result（13:5x）
- 用户口径：「task 有自己的错误处理机制，应该返回 Task<AcadApplication>」——TAP 约定失败走 faulted Task，外层不该再套 Result。**上一节记的 `Task<Result<…>>` 已作废**。
- `GetApplicationAsync (pid:int) : Task<AcadApplication>`、`GetApplicationWithRootsAsync : Task<ApplicationRoots>`；同步 `byPid` 仍返回 `Result`，不动。
- 新增 private `unwrap : Result<'T,string> -> 'T`：Error 抛 `InvalidOperationException(message)`（文案与同步版一致）；`checkPid` 不合格用 `Task.FromException<T>` 交回已完成且 faulted 的 Task，连 STA 队列都不排；队列里抛的异常由 `Sta.runAsync` 的 `TaskCompletionSource.SetException` 自然置成 faulted。
