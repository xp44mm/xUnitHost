## 新增 AutoCADHost.Application：按 PID 挂回 COM 根对象（11:4x）
- 用户要「给一个活着的 acad PID，取它的 Application 和其他根对象（如 HostApplicationServices）」。权衡后定边界：**COM 跨进程只能拿 AcadApplication + 它直属的 Documents / ActiveDocument / Preferences / MenuGroups / AcadState**；`HostApplicationServices.Current` / `Core.Application` / `DocumentManager` 是 AutoCAD 进程内 .NET 静态单例，COM 代理看不见，读它们走 `AcadMgdHost` 的 `XH_DB`（已在读 `HostApplicationServices.WorkingDatabase`）。模块里用 `Application.boundary` 三行写明，不假造。
- `AutoCADHost/Application.fs`（新，排在 Host.fs 后）：`ApplicationRoots` 记录 = 5 个 COM 根 + 纯数据现场（Pid / Hwnd / HwndPid / Version / Caption / DocumentCount / MenuGroupCount / Quiescent / 图纸名 / 命中来源）；`Application.byPid` / `byPidWithRoots` / `rootsOf` / `describe` / `describeByPid` / `boundary`。全部只读，**不新建 / 不 Quit / 不改状态**，先 `checkPid`（pid>0 且确实在 `Proc.ids "acad"` 里）。
- 认人硬判据：`AcadApplication.HWND` → `Win32.pidOfWindow` → 与给定 pid 比。先 `Com.running progIds` 直取（不枚举 ROT，守原口径），pid 对不上才 `Com.runningEntries()` 枚举逐条核 —— 多实例也不认错人。全部在 `Sta.run` 固定 STA 线程上；`describe` 只碰纯数据，可跨线程。
- `OsHost/OsHost.fs` 的 `Com` 新增 `CreateBindCtx` / `bindContext` / **`runningEntries : unit -> (string * obj) list`**（枚举 ROT、逐条取显示名与对象，单条失败跳过，上限 512，绝不新建）。黑板模式仍走 `runningAt` 不枚举。
- 验证 `xUnitHost/AcadApplicationTest.fs`（新，3 条）：`-method "*按 PID*"` 全 0 failed；真机那只 acad pid 27148 挂回成功，HWND 657248 → pid 27148，版本 23.1s，`1.dwg`，Docs 1 份 / Groups 5 组 / IsQuiescent=True，命中「ProgID 直取 AutoCAD.Application.23」；负例（自己 pid / 0）都被拒且四家进程没动；ROT 枚举兜底登记 `!AcadAppProbe.<pid>` 后列出 9 条并取回 `XUnitHost.BlackboardProbe`。回归 `-method "*通用参数表*"` 5 条 0 failed。
